# CSV schemas and serialization

Canonical storage is UTF-8, comma-delimited, period-decimal and LF-newline. The input file `input/cases.csv` has fourteen columns: `case_id`, `scenario`, three quadratic coefficients for each of `x`, `y` and `z` (`x0,x1,x2,y0,y1,y2,z0,z1,z2`), nominal bounding-sphere radii `r1,r2`, and conservative spatial `buffer`. All numeric inputs are exact dyadic multiples of 1/256 metre, represented as fixed decimal strings. The normalized trajectory interval is `[0,1]`, corresponding to a synthetic one-second motion. Input IDs must match `[A-Z0-9_]+` and scenario labels `[a-z_]+`. Missing columns, malformed numbers, nonfinite values, nonliteral expressions and domain violations are rejected.

`screening.csv`: input case ID, scenario, model version, time of candidate minimum, minimum squared margin (m²), physical surface clearance (m), minimum squared margin on the 32-step grid (m²), positive-grid status, continuous numerical classification, count of interior stationary points and value of the paceval derivative at chosen minimum. The numerical classification is distinct from the exact certificate.

`model_comparison.csv`: paceval calculation of V2 minus V1 margin and physical clearance differences, and a composed guard. `sampled_clearance.csv` and `fine_clearance.csv`: original paceval sampled values used to generate scientific figures. `formula_manifest.csv`: versioned graph formulas. `math_execution_inventory.csv`: code/data provenance and graph ownership. `native_audit.csv`: internal reference test counts. `execution_evidence.json`: actual API paths and counters. `exact_interval_certificates.csv` and `exact_interval_audit.json`: independent exact rational classification with witnesses. `high_precision_audit.json`: independent 90-digit numerical reference summaries.

The original SDK functions `paceval_dConvertStringToFloat` and `paceval_dConvertFloatToString` are used by the C++ application, with a strict decimal-literal regex ahead of input conversion. Float-to-string is not presented as universally lossless binary roundtrip. Original input coefficients are dyadic and deliberately do not depend on undocumented decimal precision. Do not reparse a rounded output CSV and assume its decimals preserve every original floating-point mantissa bit for arbitrary inputs.

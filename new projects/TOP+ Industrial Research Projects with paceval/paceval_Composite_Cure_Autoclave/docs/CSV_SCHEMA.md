# CSV provenance and schema

All CSVs are UTF-8, comma-separated, with period decimal symbols, and LF line endings. Floating-point numeric entries are first validated against a strict finite decimal literal grammar before calling the original `paceval_dConvertStringToFloat`. The C++ writer uses the original `paceval_dConvertFloatToString` for actual output fields. Conversion is not represented as guaranteed bitwise round-trip fidelity; that depends on the original SDK's formatting precision. The audit records test conditions, not universal losslessness.

`input/recipes.csv` is the sole numerical input. Its header is exact: `recipe_id,thickness_m,ramp_C_min,hold_C,hold_min,convection_W_m2K,pressure_bar`. `recipe_id` must match `R[0-9]{3}`. Other fields must be valid finite decimal literals in the stated units with bounds enforced by source code. Missing, extra, invalid, expression-like and nonfinite fields are refused before paceval graph evaluation.

`results/screening.csv` holds one row per recipe and model. Recorded columns include thickness, air schedule, conversion extrema, thermal extrema, spatially averaged chemical enthalpy and final mathematical margins. `results/cure_profiles.csv` holds the recorded ten-layer temporal snapshots. `results/model_comparison.csv` is evaluated with genuine paceval version-comparison graphs, not native subtraction. `results/high_precision_samples.csv` includes exact input values as serialized by paceval for independent mpmath checks and the original paceval local outputs. `results/native_audit.csv` contains independent native C++ checks, `results/high_precision_audit.json` contains high-precision reference metadata and `results/execution_evidence.json` captures actual graph and evaluation counts. `results/formula_manifest.csv` records real formula strings. `results/math_execution_inventory.csv` distinguishes genuine paceval expressions, reference code, and host algorithms.

**Data origin:** deterministic synthetic generator `scripts/generate_input.py`, not measured industrial process data. The official paceval source header and wrapper retain their original AGPL notices. Binary libpaceval is external and not redistributed in the research archive.

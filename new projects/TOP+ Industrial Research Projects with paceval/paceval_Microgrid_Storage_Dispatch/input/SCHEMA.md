# Deterministic synthetic input contract

The CSV files are UTF-8, ASCII numerical literals, dot decimal separators, comma-separated fields, LF line endings. Numerical columns must be finite decimal literals only: `^[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)(?:[eE][+-]?[0-9]+)?$`. The C++ program first validates this literal grammar and then calls `paceval_dConvertStringToFloat`. Strings such as `2+3`, `NaN`, `Inf`, whitespace, thousands separators and empty fields are rejected. Every row has exactly the header-defined number of columns.

`dispatch_candidates.csv` has columns `scenario,schedule_id,hour,pv_kW,load_kW,gen_kW,charge_kW,discharge_kW,import_kW,export_kW,curtail_kW,shed_kW,buy_USD_per_kWh`. Scenario is one of `grid_sunny`, `grid_cloudy`, `island_outage`; `schedule_id` is a four-digit identifier; `hour` is an integer 0 through 23. Each schedule comprises exactly 24 ordered rows. All power columns are nonnegative and measured in kW. Import and export refer to the single utility connection, with both zero during islanding. Load is the pre-curtailment demand. Shedding is permitted only for its noncritical component, with the 62% critical fraction encoded explicitly in the original paceval graph. Buy price is an illustrative USD/kWh tariff.

`parameters.csv` has `parameter,value,unit` fields. Power bounds are kW, energy is kWh, one-way efficiency is dimensionless, `dt=1 h`, and costs are hypothetical USD-based constants. Rates and cost coefficients are illustrative and not manufacturer or market measurements. No load-flow, AC frequency, voltage, battery-thermal or fuel-volume calculations are represented.

The generation code uses independent fixed seeds per candidate and a fixed model. `scripts/generate_input.py` deterministically recreates the supplied input. An intentionally invalid charge/discharge combination, power limit excess, and power imbalance occur at predetermined schedule IDs. These are negative **feasibility** examples, not schema errors.

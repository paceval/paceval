# Research CSV schemas

All CSV files are UTF-8, comma-separated, dot-decimal, finite numeric values and an initial header row. Numeric fields are parsed only after a strict decimal literal grammar and are converted via the **real original** `paceval_dConvertStringToFloat` SDK routine. Textual numeric results use `paceval_dConvertFloatToString`; its output precision is not asserted to preserve all IEEE-754 bits. Primary input is `input/candidates.csv`, with schema `candidate_id,k1,k2,k3,a,b,c,d,p1,p2,R,eps,umax` and 192 records.

Every graph input point maps to `x,y,a,b,c,d,k1,k2,k3,p1,p2,R,eps,umax` in that order. `results/screening.csv` records each model-candidate outcome, sampled state residual, analytic sufficient margins, actuator margin, violations and optional final time-trace V. `results/state_samples.csv` contains representative actual batch outputs for visualization. `results/closed_loop_traces.csv` stores the original paceval-evaluated trajectory state, control and derivative. `results/model_comparison.csv` records original paceval V2-V1 graph outputs. The function inventory, formula manifest and execution evidence are machine-readable and should be interpreted in the context of C++ source registration and executed paths.

`results/high_precision_audit.json` and `results/certificate_audit.json` come from independently executed Python scripts. They are not created by paceval and are not represented as SDK outputs. `results/reproducibility_audit.json` records hashes of main-run files compared against a separate repeat run when available. `results/ctest_summary.txt` captures executable tests, not future claims about other environments.
